materialを使うまでの手順

materialは画像やモデルそのものではなく、描き方の設定。エンティティではmaterial定義 → client entityの短い参照名 → render controllerの部位指定をつなぐ。

場所役割
materials/*.material継承元、states、defines、sampler等を設定。
materials/common.json / fancy.json / sad.json読み込むmaterialファイルのpathを追加。既存の一覧を丸ごとコピーせず追加分を書く。
entity/*.entity.jsondescription.materialsで短い参照名とmaterial名を対応付ける。
render_controllers/*.jsonMaterial.default等の参照を、モデルのboneへ割り当てる。

例えばcreator_glass:entity_alphablendは、creator_glassがentity_alphablendを継承する意味。通常のnamespace:identifierとは違う。親の設定を足すときは+states/+defines、外すときは-states/-definesを使う。

{
  "materials": {
    "version": "1.0.0",
    "creator_glass:entity_alphablend": {
      "+states": [
        "DisableCulling",
        "DisableDepthWrite"
      ]
    }
  }
}

この定義をmaterials/creator.materialへ保存する場合、登録用配列の要素は{"path":"materials/creator.material"}。client entityではdefaultをcreator_glassへ対応付け、render controllerで{"*":"Material.default"}を指定する。モデル・画像・manifestは別途必要。

参考：Bedrock Notebook — introduction

半透明・加算・乗算を選ぶ

Blendingを有効にすると、新しく描く色と背景の色を混ぜる。blendSrcは新しい色の係数、blendDstは背景色の係数。加算型の式は「新しい色×blendSrc＋背景色×blendDst」。

見た目blendSrcblendDst制作上のポイント
普通の半透明SourceAlphaOneMinusSrcAlpha画像のalphaで背景との混ざり方を変える。
光が重なるような加算OneOne重なるほど明るくなる。
alphaで強さを調整する加算SourceAlphaOnealpha=0の部分は加算されない。
背景を暗くする乗算DestColorZero白は背景を保ち、黒は暗くする。
除外合成OneMinusDestColorOneMinusSrcColor色の組合せに応じて反転に似た効果。
乗算済みalphaの画像OneOneMinusSrcAlpha画像のRGBがalphaを掛け済みの場合の組合せ。通常画像に使うと縁の見え方が変わる。

半透明を有効にしても、面の裏側や描画順の問題まで自動的に解決するわけではない。両面表示ならDisableCulling、後から描く物を深度で隠したくないならDisableDepthWriteも検討する。

参考：Bedrock Notebook — blending

面が消える・壁の向こうに見える場合

設定実際の効果混同しやすいこと
DisableCulling面の裏側も表示する。奥の物を透かして表示する深度設定ではない。
InvertCulling表示する面の表裏を反転する。モデルを左右反転する設定ではない。
DisableDepthTest前後関係の判定を省くため、壁越しに見える場合がある。複雑なモデルは自身の面の前後関係も崩れる場合がある。
DisableDepthWrite自身の深度を書かず、後から描かれる物を自身の深度で隠しにくくする。自身が壁越しに見える設定ではない。
DisableColorWrite色を出さずにほかの描画段階へ利用する。完全な非表示としてdepth/stencilの作用も消えるわけではない。

参考：Bedrock Notebook — states

depthFuncは深度比較の条件。Alwaysは比較を通し、Equalは同じ深度だけを通す。Less/LessEqual/Greater/GreaterEqualは数値上の大小を比較するため、設定値だけを「必ず手前」と覚えず描画結果も確認する。Bedrock NotebookではdepthBias系はRenderDragonで効果がないとされている。現在のちらつき対策は面を少し離すなど、モデル側の調整を先に行う。

参考：Bedrock Notebook — depth

くっきりした画像・滑らかな画像・繰り返し

samplerStatesの各要素で、対象のsamplerIndexとtextureFilter・textureWrapを指定する。複数のtexturesを指定しても、対応するmaterialがなければ任意の画像合成にはならない。

値見え方
Point画素を混ぜず、ドット絵の輪郭を保つ。
Bilinear画素間を混ぜて拡大時に滑らかにする。
Repeat画像外へ出たUVを繰り返しに使う。
Clamp範囲外では端の画素を使う。画像全体の自動拡大ではない。
{
  "+samplerStates": [
    {
      "samplerIndex": 0,
      "textureFilter": "Point",
      "textureWrap": "Repeat"
    }
  ]
}

反復が見えない場合は、UVが画像の範囲内に収まっていないかを確認する。Trilinearは環境による制限があるため、名前が候補にあるだけで常用しない。

参考：Bedrock Notebook — sampler states

definesとrender controllerを組み合わせる

define用途一緒に設定するもの
ALPHA_TESTalphaが低い画素を描かず、穴を開ける。なめらかな半透明とは別。半透明にはBlendingを検討。
USE_OVERLAY色を重ねる機能。render controllerのoverlay_color。
USE_UV_ANIM画像内の表示位置・倍率を変える。render controllerのuv_anim.offset / scale。
USE_MULTITEXTURE複数画像を扱う機能。対応するtextures配列とsampler。
USE_EMISSIVE周囲の暗さの影響を減らす発光風表示。対応する基底materialと画像形式。周囲を照らす光源ではない。
USE_COLOR_MASK素材の色変更に関する機能。対応するエンティティ・material・color設定。すべてのentityで使えるとは限らない。

definesへ任意名を追加しても新機能は生まれない。Bedrock NotebookはENABLE_FOGを現在使えない機能として扱っている。対応条件が特殊なdefineは、通常のentityへ追加するだけで使えると考えない。

参考：Bedrock Notebook — defines

モデルの部位ごとにmaterialを変える

bone名に対応するmaterialをrender controllerで指定する。*はすべて、glass_*ならその名前で始まる部位。広い指定を先に、個別の指定を後に並べると分かりやすい。

{
  "materials": [
    {
      "*": "Material.default"
    },
    {
      "glass_*": "Material.transparent"
    }
  ]
}

同じ配列内では後の一致が前の指定を上書きする。Blockbench側でbone名を揃えると、個別の列挙が減る。複数controllerを使う場合は、part_visibility等で各描画の対象も明確にする。

参考：Bedrock Notebook — multi-material models

配列内の指定順はMicrosoftのrender controller説明に合わせている。

輪郭線とマスク：複数回描画する

同じモデルを異なるmaterialで複数回描くと、単一の設定では作れない効果を構成できる。例えば本体用と少し膨らませた輪郭用のモデルを用意し、別のcontrollerとmaterialで描く。描画回数が増えるので、小さい効果から試す。

参考：Bedrock Notebook — multi-pass rendering

stencilは「印を付けた場所だけ描く／避ける」ためのマスク。最初の描画でStencilWriteとReplaceを使って印を付け、次の描画でEnableStencilTestとEqual/NotEqualを使って対象を選ぶ。frontFace/backFaceは面ごとの条件、stencilRefは印の値、ReadMask/WriteMaskは使う部分を限定する値。例えばref=8、mask=8なら同じ印を使う構成になる。

Bedrock NotebookではVibrant Visualsのstencilに版ごとの制約とほかの描画への干渉が報告されている。全範囲のmaskを無条件に使わず、本体と輪郭の順序、ほかの描画、実際に配布するモードで確認する。

参考：Bedrock Notebook — stencilling

画質設定を変えても表示を保つ

Bedrock Notebookはfancy.jsonとsad.jsonを画質設定によるmaterialの読み分けとして説明している。fancy側の登録に+definesを付けると、そのファイルのmaterialにも指定を加える構成になる。FANCY等の名前は大文字小文字を正確に使う。

片方の登録だけで制作を終えず、画質設定を切り替えて、透明・輪郭・発光風の見え方を確認する。使用する基底materialや描画モードによって効果が変わるため、配布先で必要な条件を書いておく。

参考：Bedrock Notebook — fancy

statesとdefinesの名前

statesの文字列は描画方式、definesの文字列は対応する描画機能の選択。いずれも通常のプロパティ名とは別。継承元が持つ設定を確認し、追加には+、削除には-を使う。

StencilWriteはstencil書き込み、EnableStencilTestは比較。Notebookの別ページにあるEnableStencilWriteという表記を互換名として採用しない。
